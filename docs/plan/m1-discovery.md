# M1: Discovery

Status: in progress

## Goal
A business-level picture of the CardDemo base application, produced by agents with
citations and approved by the project owner.

## Scope
- In: the base application in the reference clone (`app/cbl`, `app/cpy`, `app/cpy-bms`,
  `app/bms`, `app/jcl`, `app/data`, `app/csd`).
- Out: the optional modules (`app/app-authorization-ims-db2-mq`,
  `app/app-transaction-type-db2`, `app/app-vsam-mq`).
- Reference clone: `~/projects/reference/carddemo` at commit
  `59cc6c2fd7ebd7ef7925cad552a01a4b8b6e4d5e`. Read-only.

## Rule files
- Schema: `docs/current-state/rules/_schema.yaml`
- Analyst A output: `docs/current-state/analysis-a/rules/<PROGRAM>.yaml`
- Analyst B output: `docs/current-state/analysis-b/rules/<PROGRAM>.yaml`
- Reconciled rules (after owner review): `docs/current-state/rules/<PROGRAM>.yaml`

## Outputs (in docs/current-state/)
1. `inventory.csv` and `dependency-graph.md`, generated by `tools/inventory`
2. Rule files as above
3. `system-context.md`: users, roles, online functions, batch cycle, data stores
4. `process-maps.md`: sign-on and navigation, account maintenance, card management,
   transaction lifecycle, bill payment, interest calculation
5. `data-model.md`: entity diagram plus field-level data dictionary
6. `glossary.md` and `open-questions.md`

## Rules
- Every claim cites `path:line` in the reference clone. `tools/check_citations` must pass.
- Analysts A and B work independently in separate worktrees. Neither analysis is merged
  until both are finished and compared with `tools/diff_analyses`.
- Record uncertainty as an open question; do not guess.

## Gates (owner decides)
- G1: discovery outputs accepted
- G2: module boundaries and slice order
